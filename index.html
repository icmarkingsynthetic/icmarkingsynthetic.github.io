The motivation

Real defects are scarce.
Useful training data
should not be.

Start with a defect-free IC image. Model what causes a defect. Keep the rendering parameters and generated labels together.

The physics-informed guidelines distinguish damage to the package surface from changes to the marking itself. Scratch, contamination, missing text, smeared text, and their combinations are generated with labels taken directly from the renderer.

Scratch

Intermittent contact creates an irregular bright trace with changing width, density, and texture.

SURFACE · DEPOSITION

Contamination

Missing text

README.md +
# ICMarkingSynthetic 1.0

Synthetic images of IC package markings support defect detection and automatic labeling. The balanced collection contains 6,000 images from 40 openly licensed source photographs, with defect-free counterparts and construction-derived labels. It includes good, scratch, contamination, missing text, smeared text and combined images; it is not evidence of factory readiness.

## Start here

1. Open `examples/01_browse.ipynb` to inspect images and labels.
2. Open `examples/02_statistics.ipynb` to reproduce the composition counts.
3. Run `python examples/03_train_yolo.py --help` for the two training protocols.
4. Run `python examples/04_face_crop.py --help` to verify or recreate face crops.

Install `numpy==1.26.4 pillow pandas==2.2.3 matplotlib jupyter`; training additionally needs `ultralytics`. Notebooks have saved outputs. Run scripts from this folder.

# Files and annotation formats

Images are 8-bit grayscale PNGs. The source-disjoint train/val/test folders contain 6,000 balanced images. A capture group shares one clean capture; keep every member together when splitting.

YOLO box rows: `class center_x center_y width height`, normalized by full image width and height. Class IDs 0, 1, 2, 3 mean scratch, contamination, missing text and smeared text. Good images have empty labels; combined images have separate defect boxes, not a fifth box class.

YOLO polygon rows: `class x1 y1 x2 y2 ...`, also normalized. External contours can omit holes and smaller disconnected regions. COCO files use pixel-space boxes and polygons and are read by COCO tools.

`provenance/records.jsonl` stores the complete nested record for each balanced image; `examples/load.py` and generator regeneration read it. `provenance/counterparts/records.jsonl` resolves the 18 clean counterparts outside the balanced set. `provenance/records.csv` projects both sets into Excel-friendly columns; filter `in_balanced_6000 == yes` before counting. Component types, severities and mechanisms are ordered semicolon lists. Seeds are 64-bit integers: use string or uint64 columns, not floating point.

`face_x1`, `face_y1`, `face_x2`, `face_y2` are the recorded crop corners, identical to `roi_xyxy`. They already include the six-pixel margin and frame clipping. Do not add padding again. The raw face boundary cannot always be recovered by subtracting padding, because clipping loses information. `examples/04_face_crop.py` uses the exact recorded crop and shifts/clips annotations.

`splits/source_disjoint.csv` maps source IDs to splits. `splits/product_matched.csv` maps image IDs to splits while keeping capture groups together. `image_classes.csv` combines both protocols. Ultralytics does not read split CSV directly: its product-matched YAML contains image paths generated from these same rows. Run training from the relevant full-image or face_crop folder.

`SOURCES.csv` retains all fields from the source attribution records. `supplement_cosmetic/manifest.csv` retains nested fields as JSON strings in CSV cells. Its 467 images are not part of the balanced 6,000. `croissant.json` is the standard catalog consumed by Croissant tools. No other JSON document is merely a second human-readable description.

The provenance `sha256` field is a 16-character prefix of a decoded-pixel hash. `CHECKSUMS.sha256` stores full hashes of encoded files. These are different checks. Renderer masks are not exhaustive changed-pixel support; this limitation is retained rather than repaired silently.

# ICMarkingSynthetic

Authors: Md Sami Ul Hoque and Nasser Kehtarnavaz, Embedded Machine Learning Laboratory, University of Texas at Dallas.

Purpose: research on synthetic marking defects, detection and automatic labeling. Defects are cause-derived image-formation approximations, not first-principles material simulations. This archive contains synthetic images from openly licensed source photographs, not real evaluation frames. Missing and smeared text lack real-image evaluation in the reported study. Results are not evidence of factory readiness.

Generator contents, installation, and reproduction limits +
# ICMarkingSynthetic generator

Install from the extracted folder: `python -m pip install .` (Python 3.12).

1. **Regenerate one image:** `python scripts/regenerate_image.py --dataset ../ICMarkingSynthetic-v1.0 --id TVIC29_C000_scratch --output out --require-exact` verifies decoded-pixel identity, failing on a mismatch.
2. **Rebuild the dataset:** `python scripts/build_release.py --output rebuilt` renders the selected plan; add `--limit 50` for a short trial.
3. **Render on your prepared image:** `python examples/quickstart.py --image my_image.png --face my_face.png --marking my_marking.png` writes fresh examples using your grayscale image and binary masks.

Open `examples/quickstart.ipynb` for the executed visual walkthrough. Run commands from this folder. NumPy and OpenCV are pinned because scalar precision and interpolation changes affect exact pixels; do not upgrade them for reproduction. Notebook users can install `jupyter pandas==2.2.3` after installing this package.

| Folder or file | Purpose |
|---|---|
| icmarkingsynthetic/ | Capture, defect, label and validation implementations |
| profiles/ | Three live JSON profiles, read by load_profile() |
| sources/ | Prepared images and masks; generation_plan.json read by build_release.py, plus a human-readable CSV |
| SOURCES.csv | Full attribution and metadata for the 40 prepared sources |
| scripts/ | Prepare, calibrate, regenerate, rebuild and validate commands |
| examples/ | Executed notebook, matching Python example and new-defect template |
| tests/ | Determinism, surface confinement and profile-change tests |
| .github/workflows/ | Isolated installation and reproduction checks |
| CHECKSUMS.sha256 | File-integrity hashes |

The three profile files hold tunable defect profile parameters. `calibrate_profile.py` compares descriptor tables to evaluate their settings; it does not automatically infer every physical parameter. Mathematical constants and fixed implementation choices remain in the code. Run a fresh Python process after editing profiles. `ICMARKINGSYNTHETIC_PROFILES` may point to a temporary profile directory for an isolated experiment.

Code: MIT. Source images: CC BY-SA 4.0; annotations: CC BY 4.0. Keep SOURCES.csv and the separate license texts. Source attribution is not replaced by the code copyright.

Platform test status is recorded in TESTED_PLATFORMS.md. No unexecuted platform is claimed as passing. For your own Python or notebook session, import `icmarkingsynthetic` before NumPy, OpenCV or Matplotlib. The package selects the release-compatible NumPy CPU path automatically; the supplied scripts already use this order. If NumPy was imported first on an AVX-512 machine, restart the session and import the generator first.

Each test installs without access to another project directory, verifies `TVIC29_C000_scratch` with `--require-exact`, runs the quickstart (16 images and 16 masks, covering four severities), builds exactly 50 balanced images against frozen expected pixel hashes, and passes five unit tests. The Ubuntu sample includes the named regeneration example and 59 initial plan rows; it retains their original seeds and expected digests. A separate four-run Ubuntu matrix checks the numerical compatibility setting.

The complete Windows reconstruction matched all 6,000 balanced image digests. The distributed full-image, face-crop, mask, supplement and counterpart PNGs were also compared by file SHA-256, not merely visual similarity.

Exact reproduction is checked under Python 3.12, NumPy 1.26.4, OpenCV 4.11.0.86, Pillow 12.3.0 and Matplotlib 3.11.2. NumPy 2 changes scalar promotion; newer OpenCV kernels and NumPy's AVX-512 power implementation can alter pixels. The package disables NumPy AVX512F before NumPy initializes. Import `icmarkingsynthetic` first in a custom notebook, before NumPy, OpenCV or Matplotlib; otherwise restart the session when the package asks you to do so. This is numerical compatibility, not a change to the defect profiles or seeds.

macOS, ARM, other Python versions, and full-dataset reconstruction on Linux have not been verified. An Ubuntu small-sample pass is not a claim of full-release Linux checksum equivalence. The code refuses to report exact reproduction when a recorded pixel digest differs.
Before using the files

Renderer masks are not guaranteed to contain every changed pixel. Exact reproduction depends on the documented software versions and numerical compatibility settings. Windows full-release checks and an Ubuntu small-sample check are documented in the generator archive; other platforms remain unverified. Read both archive READMEs and the tested-platforms document. This release is not evidence of factory readiness.
